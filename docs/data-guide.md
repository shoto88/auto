# 掲載データの集め方・入力ガイド

サイトの価値の源泉は `src/data/agencies.json` のデータの**網羅性と正確さ**。ここが競合との差になる。

## データソース(優先順)

1. **各社公式サイトの料金ページ** — 料金・プラン・最低契約期間が公開されている会社から入力する。
2. **料金非公開の会社** — 問い合わせ・資料請求でヒアリングした料金レンジを載せる(非公開情報が載っていること自体が差別化になる)。掲載前に先方へ掲載可否を確認するとトラブルがない。
3. **求人・導入事例・プレスリリース** — 得意業界や実績(strengths欄)の裏取りに使う。

## 掲載基準

- 事実(料金・対応範囲・所在地・契約条件)のみを記載する。**評価・口コミ・ランキングは初期は載せない**(景表法・名誉毀損リスクを避ける)。
- 情報の取得日を管理し、半年に1回は見直す。
- 掲載拒否の申し出があれば速やかに対応する。

## agencies.json のスキーマ

| フィールド | 型 | 説明 |
|---|---|---|
| `slug` | string | URL用の一意な英数字(例: `example-inc`) |
| `name` | string | 会社名(実データでは【サンプル】を外す) |
| `isSample` | boolean | サンプルデータなら `true`。実データは `false` |
| `platforms` | string[] | `TikTok` / `YouTubeショート` / `Instagramリール` |
| `services` | string[] | 企画 / 撮影 / 編集 / アカウント運用 / 広告運用 / コンサルティング / 内製化支援 / インフルエンサーキャスティング |
| `priceMin` / `priceMax` | number | 月額料金レンジ(万円) |
| `minContractMonths` | number | 最低契約期間(ヶ月)。縛りなしは `1` |
| `location` | string | 本社所在地。オンライン完結は「オンラインのみ」 |
| `url` | string | 公式サイトURL |
| `strengths` | string | 1文で言える強み(比較表に表示される) |
| `description` | string | 詳細ページ用の紹介文(2〜3文) |

## 実データ移行時にやること

1. サンプル8社を削除し、実データに置き換える(`isSample: false`)
2. `src/layouts/Base.astro` のサンプルデータ注意書き(`.notice` のブロック)を削除する
3. `astro.config.mjs` と `public/robots.txt` の URL を本番ドメインに差し替える
